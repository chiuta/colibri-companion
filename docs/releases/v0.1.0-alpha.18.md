# Colibri Companion v0.1.0-alpha.18

Early alpha. Checked by automated tests and CI builds; **nothing was run against a real model, a graphics card, or the window on a real screen.**

**Please use alpha.18** (it includes everything in alpha.17).

## Fix
- **A model path that was refused with “config.json is missing”.** *Use this model* took anything that was not a file for a colibri model folder. Now the path is cleaned first (quotes and the invisible direction marks Windows adds when a path is copied from a file's properties), a name typed without `.gguf` is tried with it, and a folder that holds a `.gguf` file (also one level down) leads to that file. A folder with several models lists them, and a path that does not exist or a folder with no model says so, instead of asking for `config.json`.

## New
- **Gemma 4 and other families run on corbul, directly.** corbul (Companion's own engine) now runs Gemma 4 (E2B, E4B, 26B-A4B, 31B) from a `.gguf`, and `corbul serve` serves it, and the recurrent and hybrid models, over `/v1/chat/completions` and `/v1/completions` with streaming. In Companion, a GGUF of Gemma, Phi, OLMo, Granite, Mamba, RWKV and the other families that colibri does not run now goes straight to corbul, with no failed import first. See `docs/CORBUL-ARCHITECTURES.md` (8 languages).
- **Limits, honestly:** only tested on small synthetic models; **not compared with a real Gemma 4 file**. No tool calls, structured output, context packs or images for these models. Falcon, GPT-2/J/NeoX, OPT, BLOOM, MPT, gpt-oss and the other mixture-of-experts layouts are still not supported and are named in the message.
